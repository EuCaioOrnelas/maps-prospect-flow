# Wiize API — Documentação completa (para LLMs e agentes de código)

Versão: v1 · Idioma: pt-BR · Última atualização: 2026-09-04
Fonte canônica: https://wiize.com.br/api/docs

## 1. Visão geral

A Wiize API entrega inteligência comercial pronta para uso em três operações:
encontrar empresas reais, analisar a oportunidade (score + diagnóstico) e gerar
uma mensagem de abordagem personalizada.

- Base URL: `https://api.wiize.com.br/v1`
- Método: sempre `POST`, corpo JSON, `Content-Type: application/json`
- Tamanho máximo do corpo: 32 KB
- Sem mensalidade: modelo pré-pago em Wiize Tokens (1 token = R$ 0,01)
- Uso estritamente B2B, em conformidade com a LGPD

Envelope de resposta de sucesso:

```json
{
  "data": { },
  "usage": {
    "operation": "prospecting.analyze",
    "tokens_charged": 5,
    "cost_brl": 0.05,
    "balance_tokens": 4995
  },
  "request_id": "95fd8879-873d-4044-86c7-bef6a37751ff"
}
```

Sempre registre o `request_id`: ele é a referência para suporte.

## 2. Autenticação

Envie a API Key em um destes headers:

```
Authorization: Bearer wk_live_sua_chave
x-wiize-api-key: wk_live_sua_chave
```

- Chaves de produção: prefixo `wk_live_`. Chaves de teste: `wk_test_`.
- O segredo é exibido uma única vez, na criação (painel em `/api/keys`).
- Chaves enviadas por query string são rejeitadas com HTTP 400.
- Nunca use a chave no frontend/mobile: chame a API a partir do seu servidor.

Exemplo:

```bash
curl -X POST https://api.wiize.com.br/v1/prospecting/analyze \
  -H "Authorization: Bearer wk_live_sua_chave" \
  -H "Content-Type: application/json" \
  -d '{ "company": { "name": "Empresa Exemplo" } }'
```

## 3. Wiize Tokens e cobrança

| Operação | Endpoint | Custo |
| --- | --- | --- |
| Buscar empresas | `/v1/prospecting/search` | 9 tokens (R$ 0,09) |
| Analisar + diagnosticar | `/v1/prospecting/analyze` | 5 tokens (R$ 0,05) |
| Gerar abordagem | `/v1/prospecting/approach` | 4 tokens (R$ 0,04) |

- 1 token = R$ 0,01. Os tokens são reservados antes da execução e efetivados
  somente no sucesso; em qualquer falha a reserva volta ao saldo.
- Não consomem tokens: erros de autenticação, validação, rate limit, saldo
  insuficiente e falhas internas (5xx).
- Créditos são pré-pagos, não expiram e não são reembolsáveis após o consumo.
- Recarga por PIX na área de Pagamentos (`/api/billing`), a partir de R$ 30.

## 4. Endpoints

### 4.1 POST /v1/prospecting/search — 9 tokens

Encontra empresas reais por termo e localização.

Body:

| Campo | Tipo | Obrigatório | Regras |
| --- | --- | --- | --- |
| `query` | string | sim | 2–120 caracteres |
| `location` | string | sim | 2–120 caracteres |
| `limit` | number | não | 1–60, padrão 20 |

```json
POST /v1/prospecting/search
{
  "query": "padaria",
  "location": "São Paulo, SP",
  "limit": 20
}
```

Retorna em `data` a lista de empresas com nome, categoria, endereço, cidade,
telefone, website, nota e volume de avaliações (quando disponíveis).

### 4.2 POST /v1/prospecting/analyze — 5 tokens

Gera score de oportunidade (0–100), nível, probabilidade de fechamento,
diagnóstico, pontos fortes/fracos, breakdown do score e ação recomendada.

Body: objeto `company`. Obrigatório: `company.name`. Opcionais e recomendados:
`city`, `category`, `website`, `phone`, `rating`, `review_count`.

```bash
curl -X POST https://api.wiize.com.br/v1/prospecting/analyze \
  -H "Authorization: Bearer wk_live_sua_chave" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 8f2a1c34" \
  -d '{
    "company": {
      "name": "Padaria Bella Paulista",
      "city": "São Paulo",
      "category": "Padaria",
      "website": "https://padariabellapaulista.com.br",
      "rating": 4.5,
      "review_count": 56846
    }
  }'
```

Resposta:

```json
{
  "data": {
    "company_name": "Padaria Bella Paulista",
    "opportunity_score": 72,
    "opportunity_level": "Alta",
    "close_probability": "Moderada",
    "diagnosis": "...",
    "recommended_action": "...",
    "score_breakdown": { "estrutura_digital": 12, "reputacao": 18 },
    "strengths": ["..."],
    "weaknesses": ["..."]
  },
  "usage": { "operation": "prospecting.analyze", "tokens_charged": 5, "cost_brl": 0.05, "balance_tokens": 4995 },
  "request_id": "95fd8879-873d-4044-86c7-bef6a37751ff"
}
```

### 4.3 POST /v1/prospecting/approach — 4 tokens

Cria uma mensagem de abordagem personalizada. Envie `diagnosis` e `score`
obtidos no analyze para um resultado mais preciso.

```json
POST /v1/prospecting/approach
{
  "company": {
    "name": "Padaria Bella Paulista",
    "city": "São Paulo",
    "website": "https://padariabellapaulista.com.br",
    "score": 72,
    "diagnosis": "Sem cardápio digital próprio."
  }
}
```

## 5. Idempotência

Envie `Idempotency-Key: <identificador único da operação>`. Se a mesma chave for
reenviada em até 24 horas, a resposta original é devolvida sem cobrar tokens de
novo. Use sempre em retentativas após timeout de rede.

## 6. Erros

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Saldo insuficiente. Adicione créditos para continuar usando a API.",
    "request_id": "3341f379-1c62-45dd-af79-7baf3f6446d3",
    "details": { "required_tokens": 5, "available_tokens": 2 }
  }
}
```

| Código | HTTP | O que fazer |
| --- | --- | --- |
| `INVALID_REQUEST` | 400 | Corrija o formato (JSON inválido ou chave em query string). |
| `UNAUTHORIZED` | 401 | Chave ausente, inválida ou revogada. |
| `FORBIDDEN` | 403 | A chave não tem permissão para o endpoint. |
| `ACCOUNT_BANNED` | 403 | Conta/IP bloqueado por abuso. Aguarde `Retry-After`. |
| `ACCOUNT_SUSPENDED` | 403 | Conta suspensa. Contate o suporte. |
| `NOT_FOUND` | 404 | Endpoint inexistente nesta versão. |
| `METHOD_NOT_ALLOWED` | 405 | Utilize POST. |
| `INSUFFICIENT_BALANCE` | 402 | Adicione créditos em `/api/billing`. |
| `PAYLOAD_TOO_LARGE` | 413 | Reduza o corpo (limite 32 KB). |
| `VALIDATION_ERROR` | 422 | Parâmetros inválidos — veja `message`/`details`. |
| `RATE_LIMIT_EXCEEDED` | 429 | Aguarde o tempo de `Retry-After`. |
| `INTERNAL_ERROR` | 500 | Falha nossa; nada é cobrado. Repita. |
| `UPSTREAM_ERROR` / `TIMEOUT` | 502 / 504 | Não cobrado. Repita com a mesma `Idempotency-Key`. |

Estratégia recomendada: retry com backoff exponencial + jitter apenas para 429,
500, 502 e 504. Nunca faça retry automático de 400, 401, 403, 413 e 422.

## 7. Limites de uso (rate limit)

| Camada | Limite padrão | Escopo |
| --- | --- | --- |
| Rajada | 20 req / 10 s | por chave |
| Por minuto | 60 req / min | por chave |
| Por hora | 3.000 req / h | por chave |
| Conta por minuto | 300 req / min | por conta |
| Conta por 10 min | 600 req / 10 min | por conta |
| Conta por dia | 10.000 req / dia | por conta |

Headers presentes em toda resposta:

```
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 57
X-RateLimit-Reset: 1788478920
X-RateLimit-Burst-Limit: 20
X-RateLimit-Daily-Limit: 10000
X-RateLimit-Daily-Remaining: 9992
Retry-After: 27          # apenas em 429/403
X-RateLimit-Scope: key_minute   # camada atingida, em 429
```

## 8. Uso justo e bloqueios automáticos

Padrões de abuso geram bloqueio progressivo por chave, conta ou IP:
15 min → 1 h → 6 h → 24 h → 7 dias. Durante o bloqueio a API responde
`403 ACCOUNT_BANNED`.

| Comportamento | Gatilho | Como evitar |
| --- | --- | --- |
| Falhas de autenticação | 25 em 10 min | Não faça brute force; confira o segredo salvo. |
| Chave inválida/revogada | 15 em 10 min | Remova chaves antigas das integrações. |
| Estouro de rate limit | 40 em 15 min | Respeite `Retry-After` e use backoff. |
| Saldo insuficiente | 60 em 15 min | Pause a fila e recarregue. |
| Erros de validação | 150 em 10 min | Valide o payload antes de enviar. |

Também é proibido: compartilhar chaves entre empresas, revender o acesso bruto
sem transformação e prospectar pessoas físicas. Violações podem gerar bloqueio
permanente, sem estorno do saldo consumido.

## 9. Exemplo de cliente (Node.js 18+)

```js
const BASE = "https://api.wiize.com.br/v1";
const KEY = process.env.WIIZE_API_KEY;

async function wiize(path, body, idempotencyKey) {
  const res = await fetch(`${BASE}${path}`, {
    method: "POST",
    headers: {
      Authorization: `Bearer ${KEY}`,
      "Content-Type": "application/json",
      ...(idempotencyKey ? { "Idempotency-Key": idempotencyKey } : {}),
    },
    body: JSON.stringify(body),
  });

  if (res.status === 429 || res.status >= 500) {
    const wait = Number(res.headers.get("Retry-After") ?? 2) * 1000;
    await new Promise((r) => setTimeout(r, wait));
    return wiize(path, body, idempotencyKey);
  }

  const json = await res.json();
  if (!res.ok) throw new Error(`${json.error?.code}: ${json.error?.message}`);
  return json;
}

const { data: companies } = await wiize("/prospecting/search", {
  query: "clínica odontológica",
  location: "Curitiba, PR",
  limit: 10,
});

for (const company of companies) {
  const analysis = await wiize("/prospecting/analyze", { company }, `analyze-${company.id}`);
  if (analysis.data.opportunity_score >= 60) {
    const approach = await wiize(
      "/prospecting/approach",
      { company: { ...company, score: analysis.data.opportunity_score, diagnosis: analysis.data.diagnosis } },
      `approach-${company.id}`,
    );
    console.log(approach.data);
  }
}
```
